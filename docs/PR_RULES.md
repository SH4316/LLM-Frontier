# Pull Request 규칙

## 기본 원칙

- `main` 브랜치 직접 push 금지
- 모든 변경은 Pull Request로 제출
- 모델 데이터 변경은 관리자 1인의 검토 및 승인 후 병합
- LLM은 PR을 생성할 수 있지만 관리자 승인 없이 병합할 수 없음

## PR 본문 필수 항목

- 변경한 플랫폼과 모델
- 공식 출시일 출처
- 공식 소개 문서 링크
- 공식 가격 문서 링크 또는 가격 확인 불가 사유
- Frontier/가성비 분류 변경 여부
- 가성비 모델 교체·병행 유지 판단 근거
- `npm run validate` 및 `npm run build` 실행 결과

## 관리자 검토 항목

- 공식 출처 링크인지 확인
- 출시일 형식과 기존 이력 보존 여부 확인
- 모델 상태가 현재 문서와 일치하는지 확인
- 가성비 모델의 가격·대표 작업 비용 판단 확인
- 생성된 `index.html`이 Markdown 변경을 반영하는지 확인
