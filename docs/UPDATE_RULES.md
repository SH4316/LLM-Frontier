# 모델 인덱스 업데이트 규칙

이 사이트는 실시간 자동 업데이트를 사용하지 않습니다. LLM 또는 관리자가 공식 자료를 확인한 뒤 Markdown 파일을 직접 수정하고, 검토된 PR만 배포합니다.

## 1. 수정 대상

- 플랫폼별 모델 원본: `models/{platform}.md`
- 모델 사양 원본: `specs/models.md` (Context length, Open weights, 기능 및 근거)
- 메모리별 Local 추천 원본: `specs/local-models.md`
- 생성 페이지: `index.html`, `transcription.html`, `image-generation.html`, `local-models.html`
- 생성 페이지의 모델 표를 직접 수정하지 않습니다.

새 플랫폼은 `models/_TEMPLATE.md`를 복사합니다. 빌드는 `models/*.md`를 자동으로 읽습니다. 음성 전사·이미지 생성 파일은 front matter의 `type`에 `transcription` 또는 `image-generation`을 기록합니다. 언어 모델은 `language` 또는 생략합니다.

같은 플랫폼의 별도 분야 파일은 고유한 `slug`와 같은 `icon_slug`를 사용합니다. 플랫폼 아이콘은 `official_site` 도메인의 favicon을 사용하며 로딩 실패 시 플랫폼 식별 문자를 표시합니다.

## 2. 버전 기록

- 제공자가 공식 발표한 날짜를 `출시일`로 기록합니다.
- 공식 날짜가 확인되지 않으면 날짜를 추정하지 않고 `미상`으로 기록하며 PR 검토에서 확인합니다.
- 새 버전은 기존 행을 수정하지 않고 새 행으로 추가합니다.
- 과거 버전은 삭제하지 않습니다. 단종 모델은 `Deprecated`로 표시합니다.
- 출시일 내림차순으로 정렬합니다. 최신 버전이 위, 과거 버전이 아래이며 `미상`은 맨 아래에 둡니다.
- 새 버전 발표만으로 과거 모델을 단종으로 판단하지 않습니다. API 지원 종료와 공개 가중치 이용 가능 여부를 구분합니다.
- 상태 값은 `Current`, `Preview`, `Deprecated` 중 하나를 사용합니다.
- `Deprecated`는 공식 폐기 예고 또는 지원 종료입니다. 예정 종료일을 비고에 기록하며, 공개 가중치 이용 가능 여부와 API 상태를 구분합니다.
- `Current`는 현재 확인된 API 지원 또는 공개 가중치 이용 가능 상태이며, 최신 버전·유지보수 중이라는 뜻이 아닙니다. API와 공개 모델을 함께 묶은 행에서는 해당 배포 방식과 상태를 비고에 구분합니다.
- 공식 소개 문서 링크는 모든 모델 행에 필수입니다.
- 가격을 확인할 수 있는 플랫폼은 공식 가격 문서 링크도 함께 기록합니다.

## 3. 특징 태그

다음 태그만 사용합니다.

```text
코딩, 추론, Computer use, Tool call, Vision, Image input, Image generation, Transcription, 속도, 멀티모달, 장문맥, 에이전트 작업, 비용 효율
```

태그는 공식 설명과 운영상 확인된 특성을 바탕으로 수동 부여합니다. 단일 벤치마크 결과만으로 태그를 부여하지 않습니다.

`Computer use`는 화면·브라우저·GUI를 인지하고 조작하는 능력입니다. 연산 효율, MoE, 도구 호출 일반을 이 기능으로 표시하지 않습니다. `Vision`은 이미지 입력 이해입니다. 이미지 생성·편집 모델의 참조 이미지 입력은 `Image input`으로 구분하며 일반 이미지 이해 능력으로 확대하지 않습니다. 별도 vision encoder의 존재는 공식 아키텍처 자료로 확인된 경우만 메모합니다. 이미지 생성 도구 호출 지원과 모델 자체 이미지 출력을 구분합니다.

Context length는 단위와 API/앱·양자화·확장 설정을 함께 기록합니다. Open weights는 공개 가중치와 라이선스를 표시하며 오픈소스와 동일하게 취급하지 않습니다. 미확인 정보는 `미상`, 비적용 정보는 `해당 없음`으로 기록하고 기능/사양 근거 링크를 남깁니다.

Local 추천은 Unsloth 공식 자료를 우선합니다. GPU VRAM과 통합 메모리를 구분하고, 가중치 파일 크기와 KV cache·런타임 포함 메모리를 혼동하지 않습니다. 양자화와 권장 컨텍스트를 명시하며 실측과 추정치를 구분합니다.

## 4. 메인 페이지 분류

각 모델 행의 `홈 분류`에는 다음 중 하나를 기록합니다.

- `frontier`: 플랫폼별 성능·기능 기준 최상위 대표 모델을 최대 2개의 표시 항목으로 수동 선택합니다. 동일한 기반 모델의 안전장치·접근 수준 변형은 원본 타임라인·사양 행을 삭제하지 않고 명시적 큐레이션 그룹으로 한 표시 항목에 묶을 수 있습니다. 현재 Anthropic에서는 Claude Fable 5.1과 Claude Mythos 5.1을 하나의 Frontier 표시 그룹으로 묶고, 별도 모델인 Claude Opus 5를 두 번째 표시 항목으로 둡니다. 이 그룹 정책은 Anthropic에만 적용되는 3개 예외가 아니며, 모든 플랫폼의 제한은 생성기와 검증기가 계산하는 표시 항목 수를 기준으로 합니다. Flash 계열은 해당 플랫폼의 최상위라는 근거가 있을 때만 포함하며, 다루기 편하거나 저렴하거나 최신이라는 이유만으로 대표 모델로 선택하지 않습니다.
- `value`: Sonnet·DeepSeek Flash·Gemini Flash처럼 충분히 높은 성능과 기능을 유지하면서 비용이 낮아 실제 작업에 실용적인 모델을 뜻합니다. 작은 모델을 모아 둔 목록이 아닙니다.
- 작은 파라미터 수나 `mini`·`nano`·`lite`·`air` 같은 명칭, 공개 가중치, 무료 데모·무료 사용 구간만으로는 `value`로 분류하지 않습니다. 공식 가격과 대표 작업의 성능·기능·비용 근거를 함께 확인합니다.
- `specs/local-models.md`의 Unsloth 기반 메모리별 Local 추천은 로컬 실행 가능성과 메모리 요구 사항을 위한 별도 기준입니다. Local 추천 등재만으로 `value`를 부여하지 않습니다.
- 공식 가격 또는 대표 작업의 성능·기능·비용을 확인할 수 없는 모델은 근거가 확보될 때까지 `value` 후보와 가성비 비교 대상에서 제외합니다.
- `-`: 플랫폼별 Markdown 타임라인에만 기록

분류는 빌드 스크립트가 자동으로 판단하지 않습니다. 스크립트는 Markdown에 기록된 운영자의 분류를 화면에 표시할 뿐입니다.

## 5. 가성비 모델 교체 규칙

새 모델을 `value`로 추가할 때는 기존 가성비 모델과 공식 가격 및 대표 작업 비용을 비교합니다.

- 공식 가격 또는 대표 작업의 성능·기능·비용 근거가 확인되지 않은 모델은 `value` 후보로 추가하거나 기존 모델과 비교하지 않습니다. 필요한 근거가 확보된 뒤에만 검토합니다.

- 새 모델의 대표 작업 비용이 기존 모델과 큰 차이가 없고 성능·기능이 동등하거나 개선되면 기존 모델을 새 모델로 교체합니다.
- 새 모델이 더 비싸지만 코딩·추론·에이전트 작업 등에서 명확한 장점이 있으면 기존 모델과 새 모델을 모두 유지합니다.
- 판단이 불명확하면 기존 모델을 삭제하지 않고 두 모델을 함께 유지한 뒤 관리자에게 판단을 요청합니다.
- 교체 또는 병행 유지 사유는 PR 본문에 작성합니다.
- 최종 반영 전 관리자가 공식 가격과 링크를 확인합니다.

## 6. 배포 전 확인

```bash
npm run build
npm run validate
```

검증 실패 상태로 PR을 병합하지 않습니다. `index.html`이 갱신되었는지 확인한 뒤 PR에 포함합니다.

모델 표에는 Price와 추가 설명을 별도 열로 표시합니다. 중국 제공자 모델은 `specs/openrouter.md`의 확인된 OpenRouter 모델 링크·가격 스냅샷을 사용하며, 미확인 모델은 검색 링크임을 명시합니다. OpenRouter 가격은 직접 제공자 가격과 구분하고 실시간 조회하지 않습니다. 메인 페이지에는 과거 모델 전체 표를 표시하지 않습니다.
