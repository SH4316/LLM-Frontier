# 모델 인덱스 업데이트 규칙

이 사이트는 실시간 자동 업데이트를 사용하지 않습니다. LLM 또는 관리자가 공식 자료를 확인한 뒤 Markdown 파일을 직접 수정하고, 검토된 PR만 배포합니다.

## 1. 수정 대상

- 플랫폼별 모델 원본: `models/{platform}.md`
- 메인 페이지 생성 결과: `index.html`
- 메인 페이지는 Markdown 원본에서 생성되므로 모델 카드 내용을 `index.html`에서 직접 수정하지 않습니다.

새 플랫폼을 추가할 때는 `models/_TEMPLATE.md`를 복사하고, `scripts/build-site.mjs`의 플랫폼 파일 목록에 추가합니다.

## 2. 버전 기록

- 제공자가 공식 발표한 날짜를 `출시일`로 기록합니다.
- 공식 날짜가 확인되지 않으면 날짜를 추정하지 않고 `미상`으로 기록하며 PR 검토에서 확인합니다.
- 새 버전은 기존 행을 수정하지 않고 새 행으로 추가합니다.
- 과거 버전은 삭제하지 않습니다. 단종 모델은 `Deprecated`로 표시합니다.
- 상태 값은 `Current`, `Preview`, `Deprecated` 중 하나를 사용합니다.
- 공식 소개 문서 링크는 모든 모델 행에 필수입니다.
- 가격을 확인할 수 있는 플랫폼은 공식 가격 문서 링크도 함께 기록합니다.

## 3. 특징 태그

다음 태그만 사용합니다.

```text
코딩, 추론, 컴퓨트 사용, 속도, 멀티모달, 장문맥, 에이전트 작업, 비용 효율
```

태그는 공식 설명과 운영상 확인된 특성을 바탕으로 수동 부여합니다. 단일 벤치마크 결과만으로 태그를 부여하지 않습니다.

## 4. 메인 페이지 분류

각 모델 행의 `홈 분류`에는 다음 중 하나를 기록합니다.

- `frontier`: 최신 최고 성능 또는 고난도 작업에 적합한 모델
- `value`: 비용 대비 성능이 좋은 모델
- `-`: 플랫폼 타임라인에만 기록하는 모델

분류는 빌드 스크립트가 자동으로 판단하지 않습니다. 스크립트는 Markdown에 기록된 운영자의 분류를 화면에 표시할 뿐입니다.

## 5. 가성비 모델 교체 규칙

새 모델을 `value`로 추가할 때는 기존 가성비 모델과 공식 가격 및 대표 작업 비용을 비교합니다.

- 새 모델의 대표 작업 비용이 기존 모델과 큰 차이가 없고 성능·기능이 동등하거나 개선되면 기존 모델을 새 모델로 교체합니다.
- 새 모델이 더 비싸지만 코딩·추론·에이전트 작업 등에서 명확한 장점이 있으면 기존 모델과 새 모델을 모두 유지합니다.
- 판단이 불명확하면 기존 모델을 삭제하지 않고 두 모델을 함께 유지한 뒤 관리자에게 판단을 요청합니다.
- 교체 또는 병행 유지 사유는 PR 본문에 작성합니다.
- 최종 반영 전 관리자가 공식 가격과 링크를 확인합니다.

## 6. 배포 전 확인

```bash
npm run validate
npm run build
```

검증 실패 상태로 PR을 병합하지 않습니다. `index.html`이 갱신되었는지 확인한 뒤 PR에 포함합니다.
